# Payroll computation and code audit

Reviewed on 20 October 2026. This report covers the newer all-Next.js application replacing the Flask/frontend layout on `buildout`. Findings describe inspected code and synthetic reproductions; they do not establish that a breach occurred. Authentication is intentionally excluded at the owner's request and is not an implementation or release requirement for this change.

## Data flow and calculation rules

`data/employee.json` holds employee code, name, monthly salary, and an 8-, 10-, or 12-hour shift. `data/data.json` holds one active payroll, attendance, manual overrides, calculated rows, job identity, and revision. There is no external database. The existing local master contained 25 records with valid salaries, shifts, and unique codes; the active job was empty at initial inspection.

1. The first Excel worksheet, or selectable PDF text laid out as a supported attendance register, is parsed into daily records. The selected month determines dates and Sundays. Missing dates in an uploaded employee are added for review. Duplicate employee codes and duplicate daily dates are rejected.
2. Uploaded employees must match both master code and normalized name. Unmatched uploads block calculation; they are not silently dropped. Master employees absent from the register receive `not_uploaded` identity-only rows and are excluded from calculation and issue blocking.
3. Holidays are the union of Sundays, selected company holiday dates, and normalized uploaded Holiday/Weekly Off statuses. A date is counted once. Present and Absent exclude these holidays. Monthly summary overrides must reconcile to the month's length. Working on a holiday can contribute actual hours and overtime without adding a normal working-day attendance count.
4. Daily rate is monthly salary divided by either calendar days or working days (`calendar days - holidays`). A zero working-day divisor is rejected. Holiday count overrides update this divisor.
5. Absence deduction is absent days multiplied by daily rate. Expected hours are present days multiplied by shift duration. Actual hours sum work on Present/Holiday records. Late minutes sum each non-holiday present day's shortfall against shift duration, clamped at zero per day. This is a duration shortfall, not arrival-time lateness. Late fine is `late minutes / shift minutes * daily rate`.
6. Base deduction is absence deduction plus late fine. Base net is monthly salary minus deduction minus advance. Negative final payouts are allowed. Explicit overrides can replace outputs, but subsequent changes to their inputs invalidate the dependent overrides.
7. Overtime is calculated from daily punches/worked duration. Each eligible day's full excess over shift duration is counted only when the excess is greater than 15 minutes; exactly 15 minutes does not qualify. OT payment is `OT hours / OT divisor * daily rate`. Divisors are 6 for 8/10-hour shifts and 5 for 12-hour shifts. Tiffin defaults to Rs 10 per normal present day for shifts longer than eight hours. Net OT is overtime payment plus tiffin.
8. Currency results use whole-rupee rounding, halves away from zero. Intermediate rates retain precision. Therefore displayed components rounded separately can differ slightly from a final result calculated at full precision. Durations use H:MM. Statutory tax, PF, ESI, and jurisdiction-specific payroll compliance are not implemented or assessed by these formulas.

## Dependency inventory from npm audit

The audit completed after retrying outside the restricted network sandbox. Highest-severity package entries were:

- `next`: critical, including Windows RCE, Image Optimization AVIF RCE, `next/og` RCE, and other cache, disclosure, and SSRF advisories. Some require features not used by this app. The Windows advisory applies to the installed version and Windows-hosted App Router without Cache Components. The known fixes in the audit extend through the 16.3.8 patch range; choose a currently patched compatible release when updating.
- `sharp`: high native dependency advisories; determine image-optimizer reachability during remediation.
- `source-map-js`: high denial-of-service advisory; determine whether untrusted maps reach the affected parser.
- `brace-expansion`, `braces`, `js-yaml`, `micromatch`, `fast-glob`, `@next/eslint-plugin-next`, `eslint-config-next`: high direct/transitive package entries, including build/lint tooling paths.

Use `npm.cmd audit --json` to refresh this time-sensitive inventory. An advisory match is not proof of exploitation or of reachability through a particular endpoint. The audit's suggested downgrade of eslint-config-next to a different major version was not applied.

## Verification and boundaries

Regression coverage uses synthetic employees and a uniquely created temporary storage directory. It covers linked attendance/payout edits, holiday reconciliation and resets, dependent override invalidation, every editable workbook column, zero and negative values, invalid input, missing roster rows, duplicate identities, leap months, XLS/XLSX and selectable-PDF imports, workbook read-back, read-only GET, stale export rejection, concurrent revision conflicts, and the save barrier under delay/failure. Browser checks use a separate synthetic data directory rather than the personal master. Downloaded workbooks were read back to verify a focused OT-hours edit to 5:30, linked salary changes from overtime to base, a focused advance edit to 123, and genuinely blank missing-employee cells in both reports.

The app remains a personal-use payroll preparation tool. This change does not add authentication, a database, payment disbursement, statutory payroll rules, OCR, or multi-instance storage. No real employee records are included in the new source commit; removing old tracked data from this branch does not remove it from repository history.
